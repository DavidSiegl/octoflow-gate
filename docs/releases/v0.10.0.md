# The gate fails a change that closes a dependency cycle

A new check, `dependency-cycles`, fails the gate on an import a change adds that closes a cycle between the project's
own Python or Rust modules: two modules that import each other, directly or through others, can no longer be read,
tested or moved apart. The finding lies at the closing import and names the cycle's files in order.
[docs/quality-gate.md](https://github.com/DavidSiegl/octoflow-gate/blob/main/docs/quality-gate.md) says how each
language's imports are read.

- **Only new cycles**: a cycle the base already has is not a finding, even where the change adds an import to it.
- **Python**: absolute imports from the tree's top or `src/`, and relative ones; an import inside a function counts,
  one under `if TYPE_CHECKING:` does not.
- **Rust**: paths from `crate`, `self` and `super`, in a `use` or in code, resolved through the `mod` declarations;
  an import between a module and one it holds is none, and test code imports nothing.
- **Settings**: `[dependency-cycles] exempt = [...]` in `gate.toml` names the files that take part in no cycle, by
  default the tests.

A change to Python or Rust may now fail the gate where it passed under 0.9.0. Over the last 50 commits of this
repository and of octoflow-ai, 9 commits closed such a cycle, every one between sibling Rust modules.
