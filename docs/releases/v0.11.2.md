# A failing Go test says why it failed, and a moved test keeps its own skips

gotestsum writes each failure's message as `Failed` and keeps the test's output as the failure's text, and the gate
took the message, so a failing Go test was listed as `example.com/calc.TestAdd: Failed`. Where a message says no more
than that the test failed, the gate now takes the text, without the `=== RUN` and `--- FAIL:` lines `go test -v`
frames it with: the failing tests list `example.com/calc.TestAdd: calc_test.go:6: got 2, want 3`, and quality.json's
`detail` holds the test's whole output. A package that does not compile is listed as `TestMain: FAIL <package> [build
failed]`; the compiler's own words are not in gotestsum's report.

A test moved to another file, or renamed, with the attributes or decorators it already had, such as `#[cfg(unix)]` or
`#[ignore]`, is no longer reported as newly skipped (`test-integrity skip`, or `platform-only` to weigh), nor is a skip
in its body when the body is unchanged, as a Go test's `t.Skip`: the check compares them with what its old self
carried, matched by body as for `removed-test`. The same holds for a test kept in place whose attributes the diff shows
as added, as when two are reordered. Their code is compared as the test bodies are, so a comment, a string's quotes or a
trailing comma rewritten on the way changes nothing. A skip added on the way, one whose arguments changed, or a
`pytest.param` mark moved to another case is still reported.

A change that failed under 0.11.1 only on the skips such a moved, renamed or kept test already had now passes;
otherwise verdicts and exit statuses are as under 0.11.1.
