# A Rust skip is read where the parser places it

test-integrity reads the attributes of a Rust module that holds tests, and those in a test's body, as tree-sitter places
them, as it already read a test fn's own. So a skip written after other code on its line, as `#[cfg(miri)] mod tests {`
or `let x = 30; #[cfg(miri)] assert_eq!(...)`, is now found, and fails the gate; under 0.11.2 it passed. So is an inner
attribute in a test's body, `#![cfg(miri)]`, wherever the test is. A line of a multi-line string literal that starts as
an attribute, `#[ignore]` in a fixture of Rust source, is no longer read as a skip, and an attribute holding a raw
string ending in `\`, `#[doc = r"C:\"]`, no longer reads a test's existing skip below it as added: both failed under
0.11.2 and now pass.

Attributes that start on different lines are now different findings, each at its own line: a `#[cfg(miri)]` after a
wrapped platform cfg's closing bracket is a `skip` at its line, the platform cfg `platform-only` at its own, where
0.11.2 reported one `skip` at the first.

## A Rust test's expected value in a `const` or `static` is followed

test-integrity's `expected-value-changed` now follows the constants a Rust test's assertions read, as it follows
Python's: a `const` or `static` of the test's own file, outside any `fn` or `impl`, whose value calls nothing but
constructors, as `Some(3)`, and which the change edits beside the code under test, as `const EXPECTED: i32 = 30;` raised
to 31 with the fn it checks, is a finding, where 0.11.2 saw none. It is a warning, as the finding on a literal is.

## Rust test code is also a file only test code takes in, and any `#[cfg(test)]` item

A Rust file that only test code takes in, as `src/fakes.rs` under `#[cfg(test)] mod fakes;` in `lib.rs`, resolved as
rustc resolves the declaration, or that opens with `#![cfg(test)]`, is now test code whole, as a file under `tests/` is;
and so is any item marked `#[cfg(test)]`, a `fn`, an `impl` or a `const` as well as an inline module. A change that adds
or removes the `#[cfg(test)]` makes the file test code on that side only. cognitive-complexity no longer scores their
functions, which could fail the gate under 0.11.2; test-integrity now reads their tests, so a skip added to one fails
the gate where 0.11.2 passed it; and an edit inside them no longer counts as an edit to the code under test, so it arms
no `expected-value-changed` and runs no `passes-at-base`. Reading the declarations reads the tree's `.rs` files once
more when a change touches one.
