# A Rust skip is read where the parser places it

test-integrity reads the attributes of a Rust module that holds tests, and those in a test's body, as tree-sitter
places them, as it already read a test fn's own. So a skip written after other code on its line, as
`#[cfg(miri)] mod tests {` or `let x = 30; #[cfg(miri)] assert_eq!(...)`, is now found, and fails the gate; under
0.11.2 it passed. A line of a multi-line string literal that starts as an attribute, `#[ignore]` in a fixture of Rust
source, is no longer read as a skip, and an attribute holding a raw string ending in `\`, `#[doc = r"C:\"]`, no longer
reads a test's existing skip below it as added: both failed under 0.11.2 and now pass.

Attributes that start on different lines are now different findings, each at its own line: a `#[cfg(miri)]` after a
wrapped platform cfg's closing bracket is a `skip` at its line, the platform cfg `platform-only` at its own, where
0.11.2 reported one `skip` at the first.
