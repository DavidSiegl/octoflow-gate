# Rust test code leaves coverage, and mutmut runs under the tests' own pytest configuration

The coverage of new code no longer counts the lines of Rust test code that a change adds: a `#[cfg(test)]` item's, or
those of a file that is test code whole, as one under `tests/` or one only test code takes in. A passing test runs such
code whole, so its lines raised the figure over that of the code they test: a change that adds a function and a test
of it is now judged on the function alone, and can fail the coverage condition where 0.12.0 passed it.

surviving-mutants gives mutmut the pytest configuration that pytest finds for the tests mutmut runs, not only the one in
the copy's top directory: from each path mutmut's test selection names, as `tests/` finds `tests/pytest.ini`, or from
the files of the tests `--test-contexts` records under those paths. A project whose tests need that configuration's
`pythonpath`, `addopts` or plugins had its changed functions reported `not-run`, or judged under the wrong options,
under 0.12.0; they are now mutation-tested. Tests that fall under more than one configuration are a `not-run` finding
naming them, since mutmut runs all its tests under one. `--test-contexts` needs the tests named from the tree's top, as
pytest names them when its rootdir is there: where it records none so named, as `pytest tests/` beside a
`tests/pytest.ini` records them unless given `--rootdir=.`, mutmut runs its whole selection after a `not-narrowed`
finding, where 0.12.0 reported each changed function `untested`.

test-integrity's `expected-value-changed` takes a Python value written of literals alone for one literal, its sign and
its brackets with it: `assert f() == -5` becoming `== 5`, `== ("a",)` becoming `== "a"`, or `[1, 2]` becoming
`[1, 2, 3]`, beside a change to the code under test, is now a finding, where 0.12.0 saw none. Parentheses around such a
value change nothing.

vague-names no longer reports the name of a `type` or a `const` that an `impl Trait for T` holds, as serde's
`impl Visitor for V { type Value = ...; }`: the trait fixes it, as it fixes the names of the impl's fns. An inherent
impl's items are reported as before.

All findings these change are warnings, so verdicts and exit statuses are as under 0.12.0, but for the coverage
condition, which a change that adds Rust test code with the code it tests can now fail.
