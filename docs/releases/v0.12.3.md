# passes-at-base builds a Rust workspace that commits no lock file

passes-at-base runs `cargo nextest` with `--locked` only where the base tracks the workspace's `Cargo.lock`, as clippy
already did. 0.12.2 passed it always, so in a workspace that commits no lock file cargo refused to build at the base
and every changed Rust test was a `not-run` finding; such tests are now judged.

passes-at-base no longer fails to copy the base when a change moves the commit of a submodule beside the tests, as a
fixture repository under `tests/`: 0.12.2 could not remove the base's directory there, so the whole check was a
`not-run` finding. The copy now holds the working tree's submodule there, as it does the tests' other files.

The gate starts fewer processes on a large change: one `git cat-file --batch` reads all the base files of the change
that the parser checks read, where 0.12.2 started a `git cat-file` per file, and surviving-mutants asks
`cargo locate-project` for a package's workspace once, not once per changed file of the package. Which paths are Rust
code under test is decided once per path. No finding changes; a base file of the change that git lists but cannot
show now stops the gate with an error, as one in a language's file always did.

test-integrity no longer reads a Python type parameter named as a skip, as `def test_a[skip]():`, as an added skip:
Python's ast has no name there. A type parameter's bound, as `skipif` of `[T: skipif]`, is still read.

A file whose first line is a Rust inner attribute naming python, as `#![cfg(feature = "python")]`, is no longer read
as a Python script: 0.12.2 took the `#!` for an interpreter line, so an edited `.rs` file so begun was a
`cognitive-complexity not-scored` error and a `vague-names not-read` warning, as not parsing as Python.

Apart from that `not-scored` error, which failed such a change wrongly, the findings these change are warnings, so
verdicts and exit statuses are otherwise as under 0.12.2.
