# test-integrity sees more of how a Go test is weakened

test-integrity reads more of a Go test file: its legacy `// +build` lines, the platform its name names, the assertions
of a testify `assert.New` value, the calls of the file's test helpers, and its examples.

## A legacy `// +build` line is a build constraint

In a Go test file with no `//go:build` line, a `// +build` line added above the package clause is now a `skip` or a
`platform-only` finding, as a `//go:build` line is: go 1.17 and later still obey such lines there. Its space-separated
options are or'd and each option's comma-separated tags and'd, and a file's `// +build` lines are and'd, each line
judged by the constraint they make together; a term that is no tag, as `foo-bar`, is one no build sets, as go reads
it. A `// +build` line counts only above a blank line before the package clause, where go reads it, so one in the
package's doc comment does not. 0.13.0 read `//go:build` alone, so `// +build ignore` turned a file's tests off unseen.

## A Go test file renamed to a platform's name is `platform-only`

A `_GOOS`, `_GOARCH` or `_GOOS_GOARCH` suffix that a change gives a Go test file's name, as `calc_test.go` renamed to
`calc_windows_test.go`, is now a test-integrity `platform-only` finding to weigh: go builds such a file on that
platform alone. A rename that widens the suffix, as `_linux_amd64` to `_amd64` or `_android` to `_linux`, is none.
0.13.0 read no constraint from a file's name.

## A testify `assert.New` value's methods are Go assertions

In a Go test, a method called on a name bound by `:=` or `var` to testify's `assert.New` or `require.New`, as
`a.Equal(3, got)` after `a := assert.New(t)`, is now an assertion, so removing one is a `fewer-assertions` finding.
0.13.0 counted only calls of the packages' functions, as `assert.Equal(t, 3, got)`.

## A call of a test helper is an assertion of the test

In a Go test, a call of a function of the same file by its name, with the test's testing variable among its
arguments, as `check(t, Add(1, 2), 3)`, is now an assertion of the test when that function fails the test itself, by
`t.Errorf` and the like or a testify assertion, or calls another such helper, and the call's result is not kept: a
statement, a condition such as `if !ok(t, got, 3) { return }`, a `defer` or a `go`, or a helper's `return`. A fixture
whose result is bound, passed on or returned in the test, as `srv := newServer(t, ":8080")`, sets up, and is none.
Removing the call is a `fewer-assertions` finding, and changing its 3 beside the code under test an
`expected-value-changed` one. 0.13.0 counted no assertion of a test that asserts only through helpers, so it had none
to lose.

## A Go example with its output is a test

An `ExampleX()` whose body's last comment starts with `// Output:` or `// Unordered output:`, which `go test` runs and
checks the output of, is now a test whose one assertion is that comment: deleting it is a `removed-test` finding, and
changing its `// Output: 3` to `4` beside the code under test an `expected-value-changed` one. 0.13.0 read no example
as a test.

## golangci-lint reads its configuration from inside the tree only

golangci-lint now runs with `--config` naming the nearest `.golangci.yml`, `.yaml`, `.toml` or `.json` from the Go
module's directory up to the tree's top, or `--no-config` where there is none. 0.13.0 let golangci-lint look on up to
the filesystem's root and in the home directory, so a configuration there, which no change shows, could turn a linter
off.

## A Python function whose edit touches only its comments is not mutation-tested

surviving-mutants now leaves out a Python function whose file's base has a function of its name with the same code,
its decorators, parameters, defaults, annotations and body, whatever its comments and layout, as it already left out
such a Go function. 0.13.0 had mutmut test a function the change only commented, reporting what its tests already
missed. A default, a decorator or an annotation changed alone is still an edit, and in a file that holds a
`# pragma: no mutate` at the base or now, each function the change touches is mutation-tested as before.

## A Rust workspace whose tests take over a minute is mutation-tested

cargo-mutants now runs with `--minimum-test-timeout 60 --timeout-multiplier 2` in place of `--timeout 60`: each
mutant's tests have twice as long as the unmutated baseline's took, and at least 60 seconds, and the baseline runs
bounded only by `--mutation-budget`. 0.13.0's `--timeout 60` held the baseline too, so a workspace whose tests take
longer than a minute had a `not-run` finding, "did not pass (Timeout ...)", and no mutant tried.

## Go's golden files are golden files by default

The default `test-files.golden` adds `**/testdata/**/*.golden` to `**/tests/**/golden/**`, a change of the settings'
contract: a change that rewrites a Go test's `testdata/add.golden` beside the code under test now has an
`expected-value-changed` finding on it, to weigh, where 0.13.0 gave none unless the project's `gate.toml` named such
files. A `gate.toml` that sets `test-files.golden` keeps its own list.

## A Go mutant meets the whole module's tests

surviving-mutants now runs gremlins with `--coverpkg ./... --integration`: it measures coverage over the whole module
and tries each Go mutant against all of the module's tests. 0.13.0 tried a mutant against its own package's tests
alone, so a function only another package's tests run, as a helper an integration test package drives, had its
mutants reported `untested`, and one only those tests catch survived. A module's mutation testing takes longer, within
the same `--mutation-budget`.

## A stopped gate leaves no copy of the tree behind

A gate that Ctrl-C, SIGTERM or SIGHUP stops, or a panic ends, now removes the directories it made in `TMPDIR` to run
tools in, `gate-<pid>-<n>`, each holding a copy of the tree, before it exits; and each gate removes those that a gate
no longer running left there, as one killed by SIGKILL does. 0.13.0 removed them only after the check finished, so an
aborted Jenkins build left a copy of the tree in `/tmp` each time, until one filled it. SIGHUP, which 0.13.0 died of at
once, now stops the gate as SIGTERM does, exiting 130 having written no report.

Verdicts and exit statuses are otherwise as under 0.13.0.
