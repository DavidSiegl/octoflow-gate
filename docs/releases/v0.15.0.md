# Go's changed tests rerun and run at the base

flaky-tests and passes-at-base now run the Go tests a change adds or edits, surviving-mutants tries each Go mutant
against the whole module's tests, Go's golden files are golden files by default, and a stopped gate removes its copies
of the tree.

## Go's golden files are golden files by default

The default `test-files.golden` adds `**/testdata/**/*.golden` to `**/tests/**/golden/**`, a change of the settings'
contract: a change that rewrites a Go test's `testdata/add.golden` beside the code under test now has an
`expected-value-changed` finding on it, to weigh, where 0.14.0 gave none unless the project's `gate.toml` named such
files. A `gate.toml` that sets `test-files.golden` keeps its own list.

## A Go mutant meets the whole module's tests

surviving-mutants now runs gremlins with `--coverpkg ./... --integration`: it measures coverage over the whole module
and tries each Go mutant against all of the module's tests. 0.14.0 tried a mutant against its own package's tests
alone, so a function only another package's tests run, as a helper an integration test package drives, had its
mutants reported `untested`, and one only those tests catch survived. A module's mutation testing takes longer, within
the same `--mutation-budget`.

## A stopped gate leaves no copy of the tree behind

A gate that Ctrl-C, SIGTERM or SIGHUP stops, or a panic ends, now removes the directories it made in `TMPDIR` to run
tools in, `gate-<pid>-<n>`, each holding a copy of the tree, before it exits; and each gate removes those that a gate
no longer running left there, as one killed by SIGKILL does. 0.14.0 removed them only after the check finished, so an
aborted Jenkins build left a copy of the tree in `/tmp` each time, until one filled it. SIGHUP, which 0.14.0 died of at
once, now stops the gate as SIGTERM does, exiting 130 having written no report.

## flaky-tests reruns Go's changed tests

The flaky-tests check now reruns the Go tests a change adds or edits, each package's together, under `go test
-shuffle` seeds 1 to 5 in a copy of the tracked files, and reports a test whose outcome differs between seeds
(`mixed-results`), one that failed under every seed (`failed-every-run`) and one too few runs judged (`not-rerun`), as
it does Python's. 0.14.0 reran Python's tests alone, so a Go test that passed the build by luck of the order went
unseen. Each package the changed tests are in adds at most a build of its tests of five minutes and five go test
runs of 30 seconds.

## passes-at-base runs Go's changed tests at the base

When a change edits Go code outside the tests, the passes-at-base check now runs the Go tests it adds or edits in a copy
of the base with the change's `_test.go` and `testdata` files and those gate.toml's `test-support` names, each package's
together with `go test -run`, within what Rust's and Python's runs left of `--base-run-budget`, and reports one that
passes there: it does not test the change. A package whose tests do not build at the base counts as failing them. 0.14.0
ran Python's and Rust's tests alone at the base.

Verdicts and exit statuses are otherwise as under 0.14.0.
