# The gate judges the files a change has not added to git yet

`gate` judged a working tree in two halves. Its tests, coverage and clippy saw the files git does not track; its
linters, its changed lines and the copies that cargo-mutants, mutmut, gremlins and the flaky-tests reruns run in took
only what git tracks. A change that added a source file and had not run `git add` on it yet passed its tests, while
cargo-mutants' copy did not compile: its unmutated baseline failed, and the change's Rust went unmutated, with only a
warning. The new file's lines were not counted or linted either, so such a tree could pass the gate on code the gate
never judged.

Every check now takes the same tree: the files git tracks and those it neither tracks nor ignores. An untracked file
counts as one the change adds. The diff reads it through a copy of git's index with the file added intent-to-add, so
the repository's own index is not written.

A failed unmutated baseline's `not-run` finding named `mutants.out/log/baseline.log`, a log in the gate's scratch
directory, which is removed before the gate exits. The finding now says what the log said went wrong: the first test's
panic, cut as a failing test's detail is, or the first compiler or cargo error with its location, whichever comes
first, else the log's last line.
