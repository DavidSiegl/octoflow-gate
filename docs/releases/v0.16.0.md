# The gate judges the files a change has not added to git yet

`gate` judged a working tree in two halves. Its tests, coverage and clippy saw the files git does not track; its
linters, its changed lines and the copies that cargo-mutants, mutmut, gremlins and the flaky-tests reruns run in took
only what git tracks. A change that added a source file and had not run `git add` on it yet passed its tests, while
cargo-mutants' copy did not compile: its unmutated baseline failed, and the change's Rust went unmutated, with only a
warning. The new file's lines were not counted or linted either, so such a tree could pass the gate on code the gate
never judged.

Every check now takes the same tree: the files git tracks and those it neither tracks nor ignores, listed once, before
the tests run, so a file the tests write is not judged. An untracked file counts as one the change adds. The diff reads
it through a copy of git's index with the file added intent-to-add, so the repository's own index is not written; in a
sparse checkout, a file outside its cone is added too.

## What to do when upgrading

A tree that passed 0.15.3 can fail 0.16.0 when it leaves files neither tracked nor ignored, which the gate now judges
as files the change adds. Ignore them in `.gitignore`:

- a virtual environment or `node_modules/`, whose files the linters would read, ruff and mypy third-party Python;
- a `mutants/` a local mutmut run left, which fails the gate as mutmut state the change commits;
- a report of the gate's own, such as the `quality.md` of `--out`, which pymarkdown would read;
- a `Cargo.lock` cargo wrote in a workspace that commits none: clippy runs with `--locked` on a lock file among the
  judged files, and fails when the lock no longer matches the manifests.

## The failed baseline says why

A failed unmutated baseline's `not-run` finding named `mutants.out/log/baseline.log`, a log in the gate's scratch
directory, which is removed before the gate exits. The finding now says what the log said went wrong: the first test's
panic, cut as a failing test's detail is, or the first compiler or cargo error with its location, whichever comes
first, else the log's last line.
