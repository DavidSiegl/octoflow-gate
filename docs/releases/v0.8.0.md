# The gate reads Go

The checks that only read a change judge Go beside Python and Rust: test integrity, cognitive complexity and vague
names, over the `.go` files of a Go module (a `go.mod` in the file's directory or above), `_test.go` files being its
tests. [docs/quality-gate.md](https://github.com/DavidSiegl/octoflow-gate/blob/main/docs/quality-gate.md) says what
each finds in Go.

- **Test integrity** finds removed tests and subtests (`TestX/name`), `t.Skip` and an added `//go:build` line in a test
  file, fewer assertions (`t.Error*`, `t.Fatal*`, testify's `assert` and `require`), expected values changed with the
  code, and `_ = err` or an empty `if err != nil {}`. A `//go:build` line that names only platforms is weighed, not
  failed.
- **Suppressions added** include golangci-lint's `//nolint` and staticcheck's `//lint:ignore`.
- **Build configuration** names an edited `go.mod` or golangci-lint configuration, wherever it is.

A change to Go may now fail the gate where it passed under 0.7.0: a skip, a build constraint or a swallowed error added
to a test file, a function taken over the complexity limit, or a Go file that does not parse.

Go's tests are not run yet, nor its coverage measured, its code linted with golangci-lint or mutation-tested: those
come in a later release.
